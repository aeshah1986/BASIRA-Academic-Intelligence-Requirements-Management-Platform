# بصيرة (BASIRA) — منصة إدارة متطلبات التصنيفات الجامعية

منصة محلية بالعربية لإدارة مؤشرات التصنيفات الجامعية (التصنيف العربي للجامعات وQS)، وما يتعلق بها:
- المتطلبات والبيانات الناقصة.
- الجهات المسؤولة.
- المواعيد.
- المتابعات وسلّم التصعيد.
- الأدلة والأسئلة.
- التحليل التشغيلي والخطابات والتقارير.

مشروع تخرج لدورة «تطوير البرمجيات وبناء التطبيقات باستخدام Claude Code».

> **كل البيانات في المنصة تجريبية ووهمية**، ولا تمثل أي جامعة. لا تُدخل بيانات حقيقية أو شخصية.

---

## 1. التشغيل (دون تثبيت ودون إنترنت)

1. افتح المجلد `BASIRA`.
2. افتح الملف `index.html` بالنقر المزدوج، فيفتح في المتصفح (Edge أو Chrome، بإصدار حديث).
3. تظهر «لوحة القيادة» مع شريط يذكر أن البيانات تجريبية.

- لا خادم، ولا حساب، ولا اتصال بالشبكة.
- التعديلات تُحفظ في متصفحك فقط (`localStorage`).

### خيارات الرابط (اختيارية، للتجربة والفحص)
| الإضافة إلى الرابط | الأثر |
|---|---|
| (بلا إضافة) | بيانات العرض: 21 متطلبًا بتواريخ نسبية إلى اليوم |
| `?dataset=fixtures` | بيانات الفحص الثابتة F1–F6، وعليها بُنيت حالات القبول. **تُستخدم فقط عند أول تشغيل** أو بعد «إعادة البيانات التجريبية»، لأن المحفوظ في المتصفح له الأولوية |
| `?today=2026-11-01` | تثبيت «تاريخ اليوم» لتطابق الأرقام المتوقعة في `ACCEPTANCE_CRITERIA.md` |

مثال: `index.html?dataset=fixtures&today=2026-11-01`. إذا ظهرت بيانات سابقة، اضغط «البيانات»، ثم «إعادة البيانات التجريبية».

### النسخ الاحتياطي
- زر «البيانات» في الأعلى يتيح:
  - **تصدير** ملف `basira-backup-YYYY-MM-DD.json`.
  - **استيراد** ملف، مع تحقق كامل وتأكيد قبل الاستبدال.
  - **إعادة البيانات التجريبية**.
- النسخة بالإصدار 1 تُرقّى تلقائيًا.

## 2. ما في المنصة
| الصفحة | الوظيفة |
|---|---|
| لوحة القيادة | حالة كل تصنيف (الأيام المتبقية، والجاهزية، والإنجاز، والخطر وأسبابه)، والتنبيهات العاجلة، والمتأخر، والتعارضات، والأسئلة |
| التحليل التشغيلي | النواقص، ونسب الإنجاز، و6 رسوم، وترتيب الأولويات مع تفسير كل درجة، والخطوة التالية، وتصدير CSV |
| التصنيفات والمؤشرات | المؤشرات مجمعة بالمعيار، وقيمها وتعارضها، وموعد التسليم. إنشاء مؤشر وتعديله وتعطيله |
| المتطلبات | بحث فوري يتجاهل الهمزات والتشكيل، وتصفية مركبة، وإضافة وتعديل وحذف، وشروط الاكتمال، والمتابعات |
| الجهات | الجهات ومسؤولياتها ونسب إنجازها، وإعداد خطاب طلب بيانات |
| الأدلة | تسجيل وصفي للأدلة، مع التحقق منها أو رفضها بسبب |
| المتابعات | المستحقة الآن، وكل المتابعات، والأسئلة والقرارات |
| الخطابات | خطابات الطلب والتذكير والتصعيد L0–L4 من قوالب قابلة للتعديل: نسخ، وطباعة، وتسجيل الإرسال. **المنصة لا ترسل شيئًا** |
| التقارير | ما قبل الاجتماع، والمتأخرات، والأولويات، واستجابة الجهات: طباعة وCSV |
| سجل الأنشطة | كل عملية ناجحة، والأحدث أولًا |

«التحليل» **قواعد حسابية مكتوبة، لا ذكاء اصطناعي**: لا نموذج لغوي، ولا إنترنت، والنتيجة نفسها في كل مرة. الطريقة في `docs/design/09-operational-engine.md`.

## 3. الفحص
يحتاج Node.js 18 أو أحدث (جُرب على v24). لا حزم npm. من داخل مجلد `BASIRA`:

1. الفحوص الآلية للمنطق:
   ```bash
   node --test
   ```
   لا تمرر `tests/` كمسار، لأن Node 24 يرفض المجلد.
2. فحص المتصفح الحقيقي (يحتاج Edge أو Chrome مثبتًا):
   ```bash
   node tests/e2e/browser-check.js
   ```
   - يفتح `index.html` عبر `file://` في متصفح بلا واجهة، ويضغط ويكتب فعلًا.
   - يفحص كل الصفحات في 3 مقاسات، ولوحة المفاتيح، والتنزيل والاستيراد والطباعة والنسخ.
   - يستغرق نحو 3 دقائق.
   - لتحديد مسار المتصفح: متغير البيئة `BASIRA_BROWSER`.
3. تقرير الاختبار `TEST_REPORT.md` من النتائج الفعلية (يشغّل الفحصين ثم يكتب التقرير):
   ```bash
   node tests/report/build-report.js
   ```

الفحص اليدوي وحالات القبول في `ACCEPTANCE_CRITERIA.md`، والنتائج في `TEST_REPORT.md` و`TEST_LOG.md`.

## 5. الحدود (صريحة)
- **جهاز ومتصفح واحد:**
  - البيانات في `localStorage` لهذا المتصفح فقط.
  - لا مزامنة، ولا مستخدمين متعددين، ولا صلاحيات.
  - مسح بيانات المتصفح يحذفها، لذا يُنصح بالتصدير المنتظم.
- **لا إرسال:** الخطابات تُنسخ أو تُطبع، والمنصة لا ترسل بريدًا ولا تخزن بريدًا أو هاتفًا.
- **بيانات وهمية فقط:** لم تُختبر على بيانات جامعة حقيقية.
- **التحليل قواعد ثابتة:**
  - لا يفهم نص الملاحظات، ولا يتحقق من صحة الأدلة نفسها.
  - الأوزان والعتبات اختيار تشغيلي موثق، لا من منهجية التصنيف.
- **المتصفحات:** فُحص في Edge (Chromium) آليًا. Firefox وSafari وقارئ الشاشة لم تُجرب.
- **الحافظة** قد تُمنع عبر `file://` في بعض المتصفحات، فيُحدد النص للنسخ اليدوي.
- **غير منفذ بعد:**
  - محرك الحساب من الملفات المصدرية (رفع CSV/xlsx، الحالات AC-CALC).
  - معظم إضافات سد الفجوات (AC-GAP-02..09).
  - السؤال التلقائي عند الموعد الداخلي، ونموذج تعبئة CSV للجهات (AC-COM-06/10).
  - تصدير قائمة المتطلبات المصفاة (AC-RPT-07).

  التفاصيل في `TEST_REPORT.md` و`docs/KNOWN_ISSUES.md`.
