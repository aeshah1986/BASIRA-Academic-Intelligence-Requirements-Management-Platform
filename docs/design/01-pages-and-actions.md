# 01 — الصفحات والنماذج والإجراءات

> **وثيقة تصميم فقط، ولم يُنفذ منها شيء.** الأولوية بجانب كل عنصر (MUST / SHOULD / COULD) تحدد ترتيب التنفيذ ضمن الجدول المضغوط. ما لا يُنفذ لا يظهر في الواجهة (قاعدة منع الميزات الشكلية).
> القواعد والحسابات المشار إليها برموز مثل `R-…` و`C-…` معرّفة في [04-rules-and-calculations.md](04-rules-and-calculations.md)، والكيانات في [03-data-model.md](03-data-model.md).

## 0. عناصر مشتركة في كل الصفحات

| العنصر | المحتوى والسلوك | الأولوية |
|---|---|---|
| الشريط العلوي | شعار «بصيرة» يعود إلى لوحة القيادة، وعنوان الصفحة الحالية، و«اليوم: 27 أكتوبر 2026» بتقويم ميلادي وأرقام لاتينية، وزر **«البيانات»** | MUST |
| شريط البيانات الوهمية | «تعمل المنصة ببيانات تجريبية وهمية» مع رابط «إعادة البيانات التجريبية». يظهر ما دام `isSample = true`، ويختفي بعد استيراد بيانات أو أول تعديل | SHOULD |
| التنقل | **حاسوب (≥ 1024px):** شريط جانبي ثابت على **اليمين** بالصفحات السبع. **جوال (< 640px):** شريط سفلي بخمسة عناصر (القيادة، المؤشرات، المتطلبات، المتابعات، المزيد)، و«المزيد» يفتح: الجهات، والتقارير، وسجل الأنشطة | MUST |
| رسائل الحالة (Toast) | رسالة عربية قصيرة بعد كل حفظ أو حذف أو استيراد، داخل منطقة `aria-live="polite"`، وتختفي بعد 4 ثوانٍ، والأخطاء تبقى حتى تُغلق | MUST |
| حوار التأكيد | لكل حذف أو استبدال: عنوان، ونص يذكر اسم العنصر وأثره، وزرا «تأكيد الحذف» (أحمر) و«إلغاء» (التركيز الافتراضي على «إلغاء») | MUST |
| رسالة تعذر الحفظ | شريط تحذير دائم عند `persistent = false`: «الحفظ غير متاح في هذا المتصفح…» | MUST |

### حوار «البيانات» (من زر الشريط العلوي)
| الزر | الوظيفة | النتيجة | الأولوية |
|---|---|---|---|
| تصدير نسخة احتياطية (JSON) | `exportJson` | تنزيل `basira-backup-YYYY-MM-DD.json` + نشاط «تصدير» | MUST |
| استيراد نسخة احتياطية | اختيار ملف `.json` ← `parseImport` ← حوار تأكيد الاستبدال ← حفظ | نجاح: البيانات الجديدة + نشاط «استيراد». فشل: رسالة عربية بالسبب **ولا يتغير شيء** | MUST |
| إعادة البيانات التجريبية | حوار تأكيد ← `resetToSample` | تعود F1–F6 + نشاط «إعادة ضبط» | SHOULD |
| إغلاق | إغلاق الحوار وإرجاع التركيز إلى زر «البيانات» | — | MUST |

## 1. لوحة القيادة — `#/dashboard` (الصفحة الافتراضية)

**الغرض:** إجابة سؤال «ما الذي يحتاج انتباهي اليوم؟» في شاشة واحدة.

| القسم | المحتوى | الحساب | النقر يؤدي إلى | الأولوية |
|---|---|---|---|---|
| بطاقة لكل تصنيف | الاسم، وموعد التسليم، و«متبقٍ n يومًا» أو «انتهى الموعد»، و«مُدخل في المنصة n من N»، ونسبة جاهزية المؤشرات، وشارة «في خطر» | C-RANK-DAYS، C-ENTERED، C-IND-PROGRESS، C-RISK | `#/rankings` على ذلك التصنيف | MUST |
| مؤشرات رقمية (KPI) | متطلبات مفتوحة · متأخرة · قريبة الموعد · تعارضات قيم · أسئلة مفتوحة | C-OVERDUE، C-DUESOON، R-CONFLICT | `#/requirements` بالتصفية المقابلة (مثلًا «متأخرة» ← `?due=overdue`) | MUST (الأسئلة SHOULD) |
| «يحتاج انتباهك» | أعلى 5 متطلبات بترتيب الإلحاح: العنوان، والمؤشر، والجهة، وشارة الموعد | C-URGENCY | تفاصيل المتطلب `#/requirements/:id` | MUST |
| «تعارضات القيم» | المؤشرات التي تختلف قيمتها الحالية عن قيمة ملف التقدم: الرمز، والقيمتان | R-CONFLICT | `#/indicators/:id` | MUST |
| «أسئلة تنتظر قرارًا» | آخر 3 أسئلة مفتوحة | — | تبويب الأسئلة في `#/followups` | SHOULD |
| «متابعات مستحقة» | المتابعات التي حلّ موعد إجرائها التالي | C-FUP-DUE | `#/followups` | SHOULD |
| «حسب الجهة» | لكل جهة: مفتوح / متأخر (أشرطة أفقية مع الأرقام كنص) | C-BY-ENTITY | `#/entities/:id` | SHOULD |
| «آخر الأنشطة» | آخر 5 أنشطة | — | `#/activity` | COULD |

**الحالة الفارغة:** إذا لم توجد متطلبات: «لا توجد متطلبات بعد» وزر «إضافة متطلب».

## 2. إدارة التصنيفات والمؤشرات — `#/rankings`

**الغرض:** متابعة جاهزية كل مؤشر وقيمه وتعارضها.

### 2.1 صفحة القائمة
| العنصر | الوظيفة | الأولوية |
|---|---|---|
| تبويبا التصنيف («التصنيف العربي» / «QS») | تبديل التصنيف المعروض، ويُحفظ في الرابط `?ranking=ARAB` | MUST |
| رأس التصنيف | موعد التسليم، والأيام المتبقية، و«مُدخل n من N»، ونسبة الجاهزية، وزر **«تعديل بيانات التصنيف»** | MUST (التعديل SHOULD) |
| جدول المؤشرات، مجمّع حسب المعيار مثل «التعليم والتعلم (300 نقطة)» | الأعمدة: الرمز · الاسم · حالة العمل · القيمة الحالية · ملف التقدم · العام الماضي · تعارض؟ · متطلبات مفتوحة | MUST |
| تصفية المؤشرات | حالة العمل · «فيها تعارض فقط» | SHOULD |
| زر «إضافة مؤشر» | يفتح نموذج المؤشر (2.3) | SHOULD |
| النقر على صف | يفتح `#/indicators/:id` | MUST |

### 2.2 تفاصيل المؤشر — `#/indicators/:id`
| القسم | المحتوى | الأولوية |
|---|---|---|
| الرأس | الرمز، والاسم الكامل، والتصنيف ← المعيار، وشارة حالة العمل | MUST |
| بطاقة القيم | الحالية / ملف التقدم / العام الماضي / مصدر الرقم، وتنبيه «يختلف عن ملف التقدم» إن وُجد. القيم داخل `dir="ltr"` حتى لا تنقلب «1:15» | MUST |
| زر «تعديل القيم والحالة» | يفتح نموذج القيم (2.3-ب) | MUST |
| المتطلبات المرتبطة | قائمة مختصرة + زر «إضافة متطلب لهذا المؤشر» (المؤشر يُملأ مسبقًا) | MUST |
| الأسئلة والقرارات | قائمة الأسئلة + زر «إضافة سؤال» | SHOULD |
| زر «حذف المؤشر» | مسموح فقط إذا لم ترتبط به متطلبات أو أسئلة (R-DEL-IND)، وإلا يكون معطلًا مع شرح السبب | COULD |

### 2.3 النماذج
**أ) نموذج المؤشر (إضافة):**

| الحقل | النوع | إلزامي | قواعد |
|---|---|---|---|
| التصنيف | قائمة (العربي / QS) | ✓ | من `rankings` |
| المعيار | نص مع اقتراحات من المعايير الموجودة | ✓ | 2–80 حرفًا |
| الرمز | نص قصير، مثل AR-EDU-10 | ✓ | فريد، `[A-Z0-9-]` من 2 إلى 20 (R-V-CODE) |
| الاسم | نص | ✓ | 3–250 حرفًا |
| الترتيب | رقم | — | عدد صحيح ≥ 1، والافتراضي آخر ترتيب + 1 |

**ب) نموذج القيم والحالة (تعديل):**

| الحقل | النوع | إلزامي | قواعد |
|---|---|---|---|
| حالة العمل | قائمة: لم يبدأ / مسودة / محسوب بالأدلة / مُدخل في المنصة | ✓ | R-V-ENUM، وشرط «مُدخل» في R-COMPLETE-IND |
| القيمة الحالية | نص قصير | — | ≤ 30 حرفًا (R-V-VALUE) |
| قيمة ملف التقدم | نص قصير | — | ≤ 30 |
| قيمة العام الماضي | نص قصير | — | ≤ 30 |
| مصدر الرقم | نص | — | ≤ 200، مثل «ملف الموارد البشرية – تجريبي» |
| ملاحظات | نص طويل | — | ≤ 1000 |

**ج) نموذج بيانات التصنيف:** موعد التسليم* (تاريخ صالح)، ووصف الدورة (≤ 40، مثل «دورة 2026»). الاسم والرمز للقراءة فقط.

| الزر في كل نموذج | الوظيفة |
|---|---|
| «حفظ» | تحقق ← رسائل بجانب الحقول ونقل التركيز لأول خطأ، أو حفظ + نشاط + رسالة + عودة لصفحة التفاصيل |
| «إلغاء» | عودة دون حفظ. إذا تغيّرت الحقول يُسأل: «تجاهل التعديلات؟» |

## 3. إدارة المتطلبات — `#/requirements`

**الغرض:** سجل البيانات الناقصة والمهام المرتبطة بالمؤشرات.

### 3.1 القائمة
| العنصر | الوظيفة | الأولوية |
|---|---|---|
| مربع البحث «ابحث في العنوان والوصف والنواقص» | بحث فوري موحّد (AC-SRCH) | MUST |
| التصفيات | التصنيف · المؤشر · الجهة · الحالة · الأولوية · الموعد (الكل / متأخر / قريب) | MUST |
| «مسح الكل» | يفرغ البحث ويعيد التصفيات إلى «الكل» | SHOULD |
| عداد «عدد النتائج: n من N» | داخل `aria-live` | MUST |
| الترتيب | «الأكثر إلحاحًا» (افتراضي، C-URGENCY) · الموعد · آخر تحديث | SHOULD |
| حفظ حالة التصفية في الرابط | `#/requirements?due=overdue&entity=ent-hr`، لتعمل روابط لوحة القيادة وزر الرجوع | MUST |
| الجدول (حاسوب) أو البطاقات (جوال) | العنوان · المؤشر (الرمز) · الجهة · المكلَّف · الموعد + شارة · الحالة · الأولوية · آخر متابعة | MUST |
| زر «إضافة متطلب» | `#/requirements/new` | MUST |
| «تصدير النتائج CSV» | يصدّر النتائج الظاهرة فقط (AC-RPT-07) | COULD |
| الحالة الفارغة | «لا توجد نتائج مطابقة» + زر «مسح البحث والتصفية» | MUST |

### 3.2 تفاصيل المتطلب — `#/requirements/:id`
| القسم | المحتوى / الإجراء | الأولوية |
|---|---|---|
| الرأس | العنوان، وشارات الحالة والأولوية والموعد | MUST |
| البيانات | الوصف، والمؤشر (رابط)، والجهة (رابط)، والمكلَّف، والبيانات الناقصة، ورابط الدليل (يفتح في تبويب جديد مع `rel="noopener"`) | MUST |
| شروط الاكتمال | قائمة تحقق للقراءة فقط: ✓/✗ «لا نواقص مسجلة»، و✓/✗ «يوجد رابط دليل» (R-COMPLETE-REQ) | SHOULD |
| «تعديل» | `#/requirements/:id/edit` | MUST |
| «تغيير الحالة» (قائمة سريعة) | تغيير الحالة مباشرة. «مكتمل» مرفوض برسالة إذا لم تتحقق شروط الاكتمال | SHOULD |
| «حذف» | حوار تأكيد: «سيُحذف المتطلب ومتابعاته (n)». بعد الحذف عودة للقائمة | MUST |
| سجل المتابعات | الأحدث أولًا، ونموذج «إضافة متابعة» أسفله (5.2) | SHOULD |

### 3.3 نموذج المتطلب — `#/requirements/new` و`#/requirements/:id/edit`
| الحقل | النوع | إلزامي | قواعد |
|---|---|---|---|
| العنوان | نص | ✓ | بعد تنظيف المسافات: 3–150 حرفًا (R-V-TITLE) |
| الوصف | نص طويل | — | ≤ 2000 |
| التصنيف | قائمة | ✓ (للتصفية فقط) | يحدد قائمة المؤشرات، ولا يُخزَّن في المتطلب |
| المؤشر | قائمة مجمعة حسب المعيار | ✓ | موجود في التصنيف المختار |
| الجهة المسؤولة | قائمة | ✓ | موجودة |
| المكلَّف | نص | — | ≤ 80 |
| الموعد النهائي | تاريخ | ✓ | تاريخ صالح. تنبيه **غير مانع** إذا كان بعد موعد تسليم التصنيف (R-W-AFTER-RANK) أو في الماضي عند الإنشاء |
| الأولوية | أزرار اختيار: عالية / متوسطة / منخفضة | ✓ | الافتراضي متوسطة |
| الحالة | قائمة | ✓ | الافتراضي جديد، و«مكتمل» يخضع لـ R-COMPLETE-REQ |
| البيانات الناقصة | نص طويل | — | ≤ 1000 |
| رابط الدليل | رابط | — | يبدأ بـ `https://` أو `http://` (R-V-URL) |

الأزرار: **«حفظ»** (يتحقق ثم يحفظ وينشئ نشاطًا ويعود للتفاصيل)، و**«حفظ وإضافة آخر»** (COULD: يحفظ ويُبقي التصنيف والمؤشر والجهة)، و**«إلغاء»**.

## 4. الجهات والمسؤوليات — `#/entities`

**الغرض:** معرفة عبء كل جهة ومكلَّفيها وتأخرها.

| العنصر | الوظيفة | الأولوية |
|---|---|---|
| جدول الجهات | الاسم · النوع · مفتوح · متأخر · مكتمل · نسبة الإنجاز (C-ENT-PROGRESS) · المكلفون (أسماء فريدة من متطلباتها) | MUST |
| «إضافة جهة» | نموذج الجهة | SHOULD |
| النقر على جهة | `#/entities/:id`: بياناتها، ومتطلباتها مرتبة بالإلحاح، وزر «تعديل»، وزر «حذف» | MUST (العرض) / SHOULD (التعديل) |
| «حذف جهة» | مسموح فقط بلا متطلبات مرتبطة (R-DEL-ENT)، وإلا يكون معطلًا مع السبب | SHOULD |
| «عرض متطلباتها» | `#/requirements?entity=:id` | MUST |

**نموذج الجهة:**

| الحقل | النوع | إلزامي | قواعد |
|---|---|---|---|
| الاسم | نص | ✓ | 2–100، وفريد بعد التوحيد (R-V-UNIQUE-NAME) |
| النوع | قائمة: عمادة / وكالة / إدارة / وحدة / كلية / أخرى | ✓ | الافتراضي وحدة |
| جهة التواصل (وصف وظيفي) | نص | — | ≤ 100، مثل «مدير الوحدة». **لا بريد ولا هاتف** (R-V-NO-CONTACT) |
| ملاحظات | نص طويل | — | ≤ 500 |

## 5. المتابعات — `#/followups`

**الغرض:** ماذا طُلب ومتى، وما المستحق الآن، وما ينتظر قرارًا.

| التبويب | المحتوى | الأولوية |
|---|---|---|
| «مستحقة الآن» | متابعات حلّ موعد إجرائها التالي لمتطلبات غير مكتملة (C-FUP-DUE)، والأقدم أولًا | SHOULD |
| «كل المتابعات» | خط زمني لكل المتابعات من كل المتطلبات، الأحدث أولًا، مع تصفية بالجهة والنوع والفترة | SHOULD |
| «الأسئلة والقرارات» | مفتوحة أولًا ثم المحسومة، والسؤال، والمؤشر، والموجه إليه، وتاريخ الطرح، وعدد الأيام المفتوحة | SHOULD |

**نموذج المتابعة** (من تفاصيل المتطلب، أو زر «إضافة متابعة» مع اختيار المتطلب):

| الحقل | النوع | إلزامي | قواعد |
|---|---|---|---|
| المتطلب | قائمة (مثبت إذا فُتح من التفاصيل) | ✓ | موجود |
| التاريخ | تاريخ | ✓ | صالح، و**ليس بعد اليوم** (R-V-FUP-DATE) |
| النوع | قائمة: اتصال / خطاب / اجتماع / بريد / أخرى | ✓ | الافتراضي اتصال |
| الملاحظة | نص طويل | ✓ | 3–1000 بعد التنظيف |
| موعد الإجراء التالي | تاريخ | — | إن وُجد: ≥ تاريخ المتابعة |

**نموذج السؤال:** المؤشر*، والسؤال* (5–500)، والموجه إليه* (وصف وظيفي ≤ 100)، وتاريخ الطرح* (ليس بعد اليوم).
**نموذج حسم القرار:** نص القرار* (3–1000)، وتاريخ القرار* (≥ تاريخ الطرح، وليس بعد اليوم). الحفظ يحوّل الحالة إلى «محسوم» (AC-DEC-02). زر «إعادة فتح» (COULD) يعيده مفتوحًا مع نشاط.

## 6. التقارير — `#/reports`

| التقرير | المحتوى | الإجراءات | الأولوية |
|---|---|---|---|
| تقرير ما قبل الاجتماع | لتصنيف ومعيار مختارين، ولكل مؤشر: حالة العمل، والقيمة الحالية مقابل ملف التقدم (مع وسم التعارض)، والعام الماضي، والمتطلبات المفتوحة والمتأخرة مع الجهة والمكلَّف، والأسئلة المفتوحة. في الختام: «قرارات مطلوبة» | طباعة · CSV | SHOULD (هو جوهر الاستخدام الحقيقي) |
| الملخص العام | لكل تصنيف: الجاهزية، والمُدخل، والمتطلبات حسب الحالة، والمتأخر | طباعة | SHOULD |
| المتأخرات | المتأخر مرتبًا بعدد أيام التأخر، مع الجهة والمكلَّف وآخر متابعة | طباعة · CSV | SHOULD |
| حسب الجهة | لكل جهة: الإجمالي، والمكتمل، والمتأخر، ونسبة الإنجاز | طباعة · CSV | COULD |

| الزر | الوظيفة |
|---|---|
| اختيار التقرير والتصنيف والمعيار | يعيد بناء المعاينة فورًا |
| «طباعة» | `window.print()` بنسق طباعة RTL يخفي التنقل والأزرار، ويضيف التاريخ و«بيانات تجريبية» إن كانت كذلك (AC-RPT-04) |
| «تصدير CSV» | ملف UTF-8 مع BOM، باسم `basira-<نوع التقرير>-YYYY-MM-DD.csv`، وحماية من حقن المعادلات (AC-RPT-05/06، AC-SEC-04) |

## 7. سجل الأنشطة — `#/activity` (إضافة جديدة في هذه المرحلة)

**الغرض:** أثر قابل للتدقيق: ماذا تغيّر ومتى. المستخدم واحد ومحلي، فلا يُسجَّل «من».
