## أهم قرارات التصميم

| # | القرار | السبب |
|---|---|---|
| D1 | صفحة واحدة بمسارات `#/…` | تعمل عبر `file://` دون خادم، وتدعم زر الرجوع وروابط التصفية |
| D2 | مقياسان للتقدم: **إنجاز المتطلبات** و**جاهزية المؤشرات** (وزن لكل حالة عمل) | يقيسان أمرين مختلفين: العمل مع الجهات، والقرب من الإدخال في المنصة |
| D3 | الأولوية يدوية، و«الإلحاح» ترتيب محسوب بمفاتيح واضحة لا بدرجة رقمية | قابل للشرح والفحص: لكل موضع سبب |
| D4 | «مكتمل» يتطلب: لا نواقص + رابط دليل، ويُطبق عند الانتقال فقط | يطابق شرط الدليل في التصنيف العربي، ولا يكسر البيانات القديمة |
| D5 | تنبيه «في خطر» على مستوى التصنيف بثلاثة أسباب مكتوبة | المستشارة تحتاج سببًا لا لونًا |
| D6 | سجل أنشطة تلقائي داخل عملية الحفظ نفسها، بحد 500 | أثر قابل للتدقيق دون عمليات وهمية |
| D7 | البنية v2 مع ترقية تلقائية من v1 | لا تضيع بيانات أو نسخ احتياطية من المرحلة 1 |
| D8 | القيم والرموز داخل `dir="ltr"` | يمنع ظهور «1:15» معكوسة في سياق RTL |
| D9 | `ar-u-ca-gregory-nu-latn` للتواريخ | `ar-SA` وحدها تعرض الهجري |
| D10 | الجداول تتحول إلى بطاقات تحت 640px، وشريط سفلي بخمسة عناصر | لا تمرير أفقي عند 375px، وأهداف لمس ≥ 44px |

## الافتراضات (تحتاج تأكيدًا أو تصحيحًا)

| # | الافتراض |
|---|---|
| A1 | مستخدم واحد على جهاز واحد، فلا يحتاج سجل الأنشطة حقل «من» |
| A2 | «قريب الموعد» = 7 أيام (G7، كما في المرحلة 0) |
| A3 | أوزان الجاهزية: لم يبدأ 0، ومسودة ⅓، ومحسوب بالأدلة ⅔، ومُدخل 1 |
| A4 | «في خطر» عند ≤ 14 يومًا وجاهزية < 50%، أو وجود متأخر، أو متطلب موعده بعد موعد التسليم |
| A5 | مواعيد تسليم وهمية في البيانات التجريبية: العربي 2026-11-10، وQS 2026-12-27، والحقيقية تُدخل من الواجهة |
| A6 | لا رفع ملفات أدلة، ويكفي رابط الدليل (خارج النطاق، القسم 4.2 في الخطة) |
| A7 | التصنيفات ثابتة (العربي وQS)، ويُعدَّل موعدها ووصف الدورة فقط، ولا تُضاف تصنيفات جديدة من الواجهة |
| A8 | الأرقام لاتينية (0–9) في كل الواجهة، مثل منصة التصنيف |

## ما تحققت منه فعلًا في هذه المرحلة
- **التباين:** سكربت Node حسب نسب WCAG لـ 15 زوجًا لونيًا. فشل زوجان في البداية وعُدّلا، وكل الأزواج المعتمدة تنجح الآن (التفاصيل في [05 §1.2](05-visual-design.md)).
- **النماذج البصرية:** فُتحت في متصفح Claude المدمج والتُقطت لها صور. ظهرت ثلاث مشكلات وأُصلحت: نص يخرج عن بطاقة «حسب الجهة» في نموذج الحاسوب، وترتيب شاشتي الجوال المعكوس، وسطر يخرج عن بطاقة QS في الجوال. بعد الإصلاح فحص سكربت داخل المتصفح **88 نصًا في نموذج الحاسوب** (لا نص يخرج عن بطاقته) و**68 نصًا في نموذج الجوال** (لا نص يتجاوز هامش 16px).
- **الحسابات:** الأمثلة في 04 حُسبت يدويًا، ثم تحقق منها **سكربت مؤقت خارج المشروع** (ليس كود التطبيق) يقرأ `data/sample-data.js`. **كل القيم تطابقت:** المتأخر (F1 −12، F6 −7)، والقريب (F2 +4، F5 +7)، والمفتوح 5، والإنجاز 0% / 33% / 17%، والجاهزية 11% / 0%، والأيام 9 / 56، والإلحاح F1 > F6 > F2 > F5 > F4 > F3، وإنجاز الجهات، والتعارض AR-EDU-1، وعمر السؤال D1 ثمانية أيام. ستتحول إلى فحوص آلية في المرحلة 3.
- **المخططات:** **لم تُعرض فعليًا.** محاولة تحميل مكتبة Mermaid من الإنترنت داخل المتصفح منعها نظام الأمان. أُجري فحص بنيوي فقط (كل العقد معرّفة، وعلامات التنصيص متوازنة)، ولكل مخطط نسخة نصية بجانبه. ستظهر المخططات في GitHub أو في معاينة VS Code.
