# مواصفة Hook: حماية البيانات الحقيقية وبيانات الفحص (اليوم الرابع من الدورة)

> **الحالة:** مواصفة فقط، **لم تُفعَّل**. تفعيل Hooks على إعدادات حقيقية خارج نطاق المشروع (`PROJECT_PLAN.md` §4).
> الحماية الحالية **توجيه** في `CLAUDE.md` (Claude يلتزم به)، وفحص آلي في `tests/demo-data.test.js` يكشف أي اسم أو رقم حقيقي تسرّب إلى بيانات المشروع.

## الفرق بين التوجيه والإنفاذ
| | التوجيه (`CLAUDE.md`) | الإنفاذ (Hook) |
|---|---|---|
| الآلية | تعليمات يقرؤها Claude ويلتزم بها | سكربت ينفذه Claude Code قبل الأداة، ويمنعها بغض النظر عن التعليمات |
| عند الخطأ | يعتمد على التزام النموذج | تُرفض العملية برسالة |
| في المشروع | مفعّل | مواصفة أدناه |

## المواصفة المقترحة
- **الحدث:** `PreToolUse` على الأدوات `Write` و`Edit` و`NotebookEdit` و`Bash`.
- **القاعدة 1 (منع):** أي مسار يبدأ بـ `C:\Users\User\Desktop\ملف التصنيفات العربية\` يُرفض بالرسالة: «هذا المجلد مرجع للقراءة فقط وفيه بيانات حقيقية».
- **القاعدة 2 (طلب تأكيد):** تعديل `data/sample-data.js` يُوقف ويُطلب تأكيد المستخدمة، لأن حالات القبول مبنية عليه.
- **القاعدة 3 (منع):** أوامر `git push` تُرفض، فلا نشر دون موافقة.

مثال إعداد (`.claude/settings.json`، غير مضاف إلى المشروع):
```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Write|Edit|NotebookEdit|Bash",
        "hooks": [{ "type": "command", "command": "node .claude/hooks/guard.js" }] }
    ]
  }
}
```
`guard.js` يقرأ مدخل الأداة من stdin، ويفحص المسار أو الأمر وفق القواعد أعلاه، ويخرج برمز 2 مع رسالة للرفض.
