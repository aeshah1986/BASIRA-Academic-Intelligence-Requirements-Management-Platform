# بطاقة المهمة الآلية (اليوم الخامس من الدورة)

**المهمة:** توليد تقرير التحقق `TEST_REPORT.md` من تشغيل فعلي على نسخة نظيفة.

| البند | القيمة |
|---|---|
| **المشغّل** | يدويًا قبل كل حفظ مرحلة أو تسليم: `node tests/report/build-report.js`، أو عبر مهارة `basira-review` (الخطوة 4) |
| **المدخلات** | ملفات المشروع المتتبعة وغير المتتبعة (دون `.git` ودون المخرجات السابقة)، و`ACCEPTANCE_CRITERIA.md`، و`tests/report/ac-map.js`، و`tests/report/notes.md` |
| **الإجراء** | 1) نسخ إلى مجلد مؤقت نظيف. 2) `node --test` (منسق TAP). 3) `node tests/e2e/browser-check.js` (Edge أو Chrome بلا واجهة عبر `file://`). 4) فحوص README والتسليم وأدوات الجودة R-01..R-09. 5) ربط كل حالة قبول بفحوصها. 6) حذف المجلد المؤقت |
| **المخرج** | `TEST_REPORT.md` (لكل حالة: المعرّف، والخطوات، والمتوقع، والفعلي، والحالة، والدليل)، و`tests/report/output/` (unit-tap.txt، وe2e-output.txt، وe2e-results.json، وrun-meta.json) |
| **عند الفشل** | يبقى التقرير صادقًا: الفحص الفاشل يظهر «❌ فاشل» مع تفاصيله، والحالة بلا فحص «⚪ لم يُختبر»، والوظيفة الناقصة «⛔ غير منفذ». إذا لم يوجد متصفح، تفشل R-03 وتظهر حالات المتصفح فاشلة، ولا تُعرض نجاحات وهمية. إذا تعذر حذف المجلد المؤقت، يطبع تنبيهًا باسمه |
| **المدة** | نحو 3 دقائق |
| **الحدود** | يعيد استخدام آخر مخرجات بـ `--reuse` دون تشغيل، والتاريخ في التقرير يبين وقت التشغيل الفعلي |
